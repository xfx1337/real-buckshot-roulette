# Buckshot Roulette IRL - Состояние проекта

Привет! Если ты следующий ИИ-агент, читающий этот файл — здесь собрана вся архитектура, логика и костыли проекта, чтобы тебе было проще понять текущее состояние дел.

## 🎯 Суть проекта
Адаптация игры *Buckshot Roulette* для игры в реальной жизни (IRL) с физическим инвентарем (дробовик, предметы, стопки с жидкостями). 
- Это **мультиплеерная** версия (2-4 игрока).
- Пятый человек — это **Дилер** (Game Master). Дилер управляет логикой через планшет/ПК, выдает физические предметы, заряжает физический дробовик и нажимает кнопки на сервере от имени игроков.
- Игроки используют свои смартфоны (горизонтальная ориентация) только как **мониторы** для отслеживания своего здоровья и хода. Они не нажимают кнопок в телефоне.
- "Без смертей": При потере всех HP игрок выбывает до конца **текущего раунда**. В начале следующего раунда **все игроки воскрешаются** с полным здоровьем (по правилам раунда). Победителем становится последний выживший в самом последнем раунде.

## 🛠 Технический стек
- **Backend:** Python + FastAPI + Uvicorn
- **Состояние и связь:** Глобальный объект `GameEngine` в памяти. Связь с клиентами через **WebSockets** (мгновенное обновление UI).
- **Frontend:** Vanilla HTML, CSS, JS (шаблонизатор Jinja2 для роутинга). Стилизация под ретро-терминал (JetBrains Mono, CRT-эффекты, только черный, зеленый и красный цвета).

## 🗂 Архитектура и файлы
1. `server.py`
   - Поднимает FastAPI.
   - Хранит глобальную переменную `game = GameEngine()`.
   - Содержит все REST endpoints (`/api/...`) для действий дилера.
   - Управляет WebSockets (`/ws/dealer`, `/ws/player/{id}`), транслируя изменения состояния (`broadcast_state`).

2. `game_engine.py`
   - Вся бизнес-логика. Машина состояний (`GamePhase`).
   - `GameEngine` управляет подключением, стадиями раундов, генерацией патронов, применением предметов (лекарство, адреналин и т.д.).

3. `templates/dealer.html`
   - Интерфейс Дилера. Содержит панели для всех фаз (Лобби, Зарядка, Предметы, Ход Игрока, Конец раунда).
   - Дилер видит **всё**: порядок патронов, точные результаты применения лупы/телефона, содержимое лекарства. Добавлена возможность скрывать количество патронов на экранах игроков (включается в настройках лобби).

4. `templates/player.html`
   - Интерфейс Игроков (полностью на английском языке, в нижнем регистре). Показывает только: их номер, жизни (молнии) и статус (`[ this player turn ]`, `[ handcuffed ]`). Имеет визуальные анимации при смене раунда (римские цифры и круги).

5. `static/style.css`
   - Стили проекта. Специфично настроены для landscape отображения на телефонах (ограничение в 7 молний-жизней на строку, высота 80vh).

## ⚙️ Важные механики и костыли (Обрати внимание!)
- **Генерация патронов:** В первом раунде жестко захардкожено `1 Боевой, 2 Холостых` для каноничности старта. В остальных раундах есть защита от сильных перекосов (например, при 6 патронах никогда не сгенерируется 5 боевых и 1 холостой, только балансные 4:2, 3:3, 2:4). Третий раунд ограничен 6 патронами.
- **Лекарство (Expired Medicine):** Чтобы дилер мог **до** использования игроком налить ему нужную жидкость (воду или водку), лекарство генерируется *сразу при выдаче*. Оригинальный `EXPIRED_MEDICINE` при раздаче заменяется на `MEDICINE_VODKA` или `MEDICINE_WATER`. Дилер в логах и инвентаре видит тип жидкости, игрок — нет.
- **Адреналин:** Когда применяется адреналин, предмет просто перекладывается в инвентарь ворующего (в реальности дилер забирает физический предмет у одного и кладет перед другим). Использовать украденный предмет дилер должен отдельным кликом. Это *фича*, так как в IRL дилеру удобнее разделить действия "Забрал" и "Применил".
- **Всплывающие окна дилера (Лупа, Телефон, Лекарство):** В UI дилера результаты показываются в модалке. При нажатии "OK" фронтенд шлет запрос на `/api/clear_special`, который затирает эти результаты на сервере. Это нужно, чтобы модалка не всплывала повторно при каждом следующем WebSocket апдейте.
- **Наручники:** Переменная `handcuffs_state` (0, 1, 2) позволяет визуальной надписи `[ handcuffed ]` оставаться на экране игрока ровно до тех пор, пока ход, который он пропустил, фактически не завершится.
- **Телефон:** Не дает никакой информации (и тратится впустую), если в дробовике осталось 2 или меньше патронов (для баланса).
- **Сквозная очередь ходов:** Индекс текущего хода не сбрасывается к "Игроку #1" при перезарядках. Ходы передаются плавно, переходя к следующему игроку даже после окончания раунда.
- **Анимации и задержки:** При окончании раунда (или смерти) игрок видит свой итоговый статус 5 секунд, после чего запускается красивая CSS-анимация перехода к следующему раунду.
- **Сброс после игры:** После завершения игры у игроков есть 8-секундный таймер, после которого их интерфейс автоматически редиректит на главную страницу (для подготовки к новой партии). Вход дилера скрыт из основного меню (`/dealer` вводится вручную).

## 🚀 Как запускать
```bash
python server.py
```
Сервер будет доступен на `http://0.0.0.0:8000`.

## 📌 Что может понадобиться в будущем
- Сохранение настроек (конфигурации раундов и весов предметов) в `json` файл, чтобы они не сбрасывались при перезапуске сервера (сейчас сбрасываются в дефолтные).
- Улучшение UI Дилера под планшеты, если элементы станут слишком мелкими.
- Защита от отключения по таймауту или потери WebSocket (базовый реконнект уже реализован во фронтенде).
