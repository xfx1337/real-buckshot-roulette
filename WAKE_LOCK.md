# Удержание экрана (Wake Lock)

Экран игрока не должен гаснуть, пока открыта страница `player.html`, даже если
пользователь не касается устройства. За это отвечает модуль
[`app/static/wakeLock.js`](app/static/wakeLock.js).

## Как это работает

Прогрессивная стратегия, два механизма:

1. **Основной — [Screen Wake Lock API](https://developer.mozilla.org/docs/Web/API/Screen_Wake_Lock_API)**
   (`navigator.wakeLock.request('screen')`). Правильный путь, но работает
   **только в secure context** — HTTPS или `localhost`.
2. **Фолбэк — [NoSleep.js](https://github.com/richtr/NoSleep.js)** (`v0.12.0`,
   вендорится в `app/static/nosleep.min.js`). Держит экран через зациклённое
   скрытое видео. Работает на обычном HTTP и в браузерах без Wake Lock API.

Ручной видео-хак **не дублируется** — вся фолбэк-логика внутри NoSleep.js.

Триггер — только пользовательский жест: тап по оверлею `tap to start`
(`#fullscreen-gate`) вызывает `wakeLockMgr.enable()`. Авто-запуска при загрузке
нет (autoplay-политики его всё равно бы заблокировали).

При возврате вкладки в фокус (`visibilitychange` → `visible`) лок
переустанавливается: ОС отбирает нативный лок, пока вкладка скрыта. При скрытии
или закрытии страницы (`pagehide`) и при явном `disable()` лок освобождается.

Состояние логируется в консоль (`acquired` / `released` / `fallback-triggered` /
`failed`) и отражается индикатором в правом верхнем углу
(`screen on` / `screen on*` фолбэк / `screen sleep` / `sleep err`). Колбэк
`analytics` в модуле есть, но в проекте пока нет бэкенд-аналитики, поэтому не
подключён — событие уходит только в консоль.

## ⚠️ Secure context — важно для этого проекта

Игра раздаётся по локальной сети на **голом HTTP** (`http://192.168.1.X:8000`,
см. README). Это **не** secure context, поэтому нативный Wake Lock API там молча
отклоняется — **основным реально работающим механизмом в проде становится
NoSleep.js**. Нативный путь включается только если открыть страницу по HTTPS или
через `localhost`.

Если нужен нативный Wake Lock в проде — раздавать по HTTPS (обратный прокси с
TLS-сертификатом перед сервером).

## Поддержка браузеров

| Браузер / платформа        | Native Wake Lock API | Фолбэк NoSleep.js | Итог          |
|----------------------------|----------------------|-------------------|---------------|
| Chrome / Edge (Android)    | ✅ (только HTTPS)    | ✅                | Работает      |
| Chrome / Edge (Desktop)    | ✅ (только HTTPS)    | ✅                | Работает      |
| Safari iOS 16.4+           | ✅ (только HTTPS)    | ✅                | Работает      |
| Safari iOS < 16.4          | ❌                   | ✅                | Через фолбэк  |
| Firefox (Desktop/Android)  | ⚠️ частично / off   | ✅                | Через фолбэк  |
| In-app WebView (Telegram/IG)| ❌ обычно           | ⚠️ нестабильно    | Только QA     |
| Любой браузер по HTTP      | ❌ (insecure)        | ✅                | Через фолбэк  |

## Чек-лист ручного QA (реальные устройства)

Автотесты проверяют только логику. Реальную блокировку экрана проверять руками:

- [ ] **iOS Safari (HTTPS)**: тап `tap to start` → индикатор `screen on`, экран
      не гаснет ≥ 5 мин без касаний.
- [ ] **iOS Safari (HTTP, локальная сеть)**: индикатор `screen on*` (фолбэк),
      экран не гаснет ≥ 5 мин.
- [ ] **Android Chrome (HTTP, локальная сеть)**: индикатор `screen on*`, экран
      не гаснет ≥ 5 мин.
- [ ] **Android Chrome (HTTPS)**: индикатор `screen on`, экран не гаснет.
- [ ] **Возврат из фона**: свернуть вкладку/приложение на ~30 сек, вернуться →
      экран снова держится (лок переустановлен).
- [ ] **In-app WebView** (если игроки заходят по ссылке из мессенджера —
      Telegram / Instagram / WhatsApp): проверить, держится ли экран; фолбэк тут
      нестабилен, зафиксировать результат.
- [ ] **Долгая сессия** (≥ 30 мин): экран всё ещё держится, батарея не сажается
      аномально.
- [ ] **Выход/закрытие**: закрыть вкладку → устройство гаснет по обычному
      таймауту (лок освобождён, не остаётся «залипшим»).

## Известные ограничения

- **HTTP = нет нативного лока.** В проде (локальная сеть, HTTP) работает только
  NoSleep.js-фолбэк.
- **Энергосбережение ОС.** Агрессивный power-save (Android Battery Saver, iOS Low
  Power Mode) может гасить экран даже при активном локе, особенно на очень долгих
  сессиях. Полной гарантии на уровне ОС нет.
- **In-app WebView** (мессенджеры) часто ломают и нативный лок, и NoSleep — там
  поведение непредсказуемо, только ручная проверка.
- **Восстановление фолбэка без жеста.** NoSleep-видео требует пользовательский
  жест. При возврате из фона модуль переустанавливает лок, но повторный
  `noSleep.enable()` без жеста на iOS может быть отклонён autoplay-политикой.
  Чтобы не спамить отклонёнными вызовами, модуль не дёргает `enable()`, если
  фолбэк уже был поднят. Если ОС всё же поставила видео на паузу за долгий фон —
  гарантии восстановления без нового тапа нет.
- **iOS < 16.4** — только фолбэк-видео (нативного API нет).

## Тесты

```bash
npm install          # поставить @playwright/test и nosleep.js
npm run vendor:nosleep   # обновить app/static/nosleep.min.js из node_modules (при апгрейде)
npm test             # запустить логические тесты (tests/wake-lock.spec.ts)
```

Тесты мокают `navigator.wakeLock` и `window.NoSleep`, проверяют вызов по клику,
переустановку на `visibilitychange`, срабатывание фолбэка и освобождение при
`disable()`. **Реальную блокировку экрана они не проверяют** — см. чек-лист выше.
