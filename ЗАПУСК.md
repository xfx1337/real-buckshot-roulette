# Запуск Buckshot Roulette IRL

Веб-сервер для живой игры «Buckshot Roulette» на 2–4 игрока + 1 дилер (ведущий).
Игроки используют телефоны как экраны-мониторы; все физические действия
(выстрелы, предметы, перезарядка) фиксирует дилер через свою панель.

Стек: Python + FastAPI + WebSocket, Docker. Опционально: ESP32 (физический
курок/соленоид) и TV-режим с видео и CCTV.

---

## Быстрый старт (одна команда)

```bash
./start.sh
```

Скрипт делает по шагам:
1. **Автонастройка сети** — определяет Wi-Fi (SSID/пароль) и LAN-IP хоста,
   вписывает в `config.json` (через `scripts/net_config.sh`).
2. **Прошивка ESP32** — заливает настройки на плату по USB (`esp/flash.sh`).
   Идёт на хосте, не в Docker. Плата не подключена — шаг пропускается.
3. **Сервер в Docker** — `docker compose up --build`, наружу на LAN-IP хоста.

После старта сам открывает браузер на `/dealer`. Первый запуск уводит на
мастер `/setup` (заполнить Wi-Fi + адрес сервера). Останов — `Ctrl+C`.

### Флаги
```bash
./start.sh --no-flash   # не трогать плату (только сеть + сервер)
./start.sh --no-net     # не переопределять сеть в config.json
./start.sh --sudo       # разрешить sudo для добычи скрытого SSID (macOS 26+)
./start.sh --detach     # сервер в фоне (docker compose up -d)
./start.sh --down       # остановить сервер и выйти
./start.sh --help       # справка
```

## Требования

- **Docker + docker compose** (Docker Desktop на macOS/Windows).
- Все устройства (телефоны игроков, планшет дилера, TV) в **одной Wi-Fi сети**.
- Для прошивки ESP32: `arduino-cli` + плата по USB. Без железа игра полностью
  работает вручную через панель дилера — запускай `./start.sh --no-flash`.

## Роли и страницы

Один сервер, разные устройства подключаются к нему по LAN-IP хоста
(`http://<IP>:8000`, `<IP>` печатает `start.sh`):

| Роль | Устройство | Адрес |
|------|-----------|-------|
| **Дилер** (ведущий) | планшет/ПК | `/dealer` |
| **Мастер настройки** (первый запуск) | тот же | `/setup` |
| **Игроки** | телефоны | `/` → «join game» |
| **Игроки (TV-режим)** | телефоны | `/telejoin` → `/teleplayer/<id>` |
| **Показ-экран** (скрытые сообщения: лупа, телефон) | доп. монитор | `/showscreen` |
| API-доки (Swagger) | отладка | `/docs` |

### Режимы игры
- **Мультиплеер (2–4 игрока):** каждый со своего телефона, экран горизонтально
  перед игроком (HP + чей ход).
- **Соло / 1v1 (игрок против дилера):** один игрок, виртуальный `DEALER`.
  Телефон — центральный монитор, split-screen (две HP-шкалы). Эксклюзив —
  «просроченное лекарство» (50/50: +2 HP или −1 HP).

## Видео и камеры (TV-режим)

Опциональный слой поверх игры — для антуража. Не нужен чтобы играть.

### TV-видео
Ролики играют на экранах (`/showscreen`, teleplayer): помехи (белый шум),
интро, победа/поражение. Управление — в панели дилера (раздел TV).

- Файлы кладутся в `app/videos/` (`.mp4`).
- Слоты и автозапуск — `app/video_config.json`:
  - `videos` — какой файл в каком слоте (`static_noise`, `intro`,
    `player_win`, `player_lose`);
  - `auto_play` — что играть само (помехи при создании игры, результат на
    game over);
  - `loop`, `settings.volume`.
- Каталог `app/videos/` создаётся автоматически; без файлов слоты пустые.

### CCTV (телефон как камера)
Трансляция с телефона на TV-экран через медиасервер **MediaMTX**.
Включается из панели дилера. Кнопка «запустить CCTV-сервер» дёргает
`/api/cctv/start_server`.

⚠ **Ограничение:** авто-скачка MediaMTX качает `mediamtx.exe` —
**только Windows**. На macOS/Linux поставь MediaMTX вручную
(https://github.com/bluenviron/mediamtx) и запусти его на хосте отдельно.
Плюс сервер игры в Docker не может сам поднять MediaMTX хоста — на mac/Linux
это ручной шаг. Фича экспериментальная.

## Настройка `config.json`

Единый источник настроек. Создаётся из `config.example.json` (сам `start.sh`
или мастер `/setup`). В git не хранится (Wi-Fi пароль) — в репо только пример.

```json
{
  "server": { "host": "0.0.0.0", "port": 8000 },
  "esp": {
    "wifi_ssid": "...", "wifi_password": "...",
    "server_base_url": "http://<IP>:8000",
    "pins": { "trigger": 4, "solenoid": 5, "live_led": 2 },
    "trigger_remote": { "code": 0, "protocol": 1, "bitlength": 24 }
  }
}
```

- `server.host: 0.0.0.0` — слушать все интерфейсы (телефоны/плата достучатся).
- `server.port` — host-порт (проброс наружу из контейнера). Смени если 8000 занят.
- Блок `esp` — Wi-Fi/пины/RF-код платы. Нужен только для ESP32; те же значения
  прошиваются в плату (`esp/flash.sh` → `esp/config.h`). Заглушки из примера
  (`YOUR_WIFI_SSID`, `192.168.1.100`) заставляют сервер открыть мастер `/setup`.

`config.json` монтируется в контейнер read-write — правки из `/setup`
пишутся в него без пересборки образа.

## Запуск без Docker (dev)

```bash
# из корня проекта
python3 -m venv venv && source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp config.example.json config.json                 # Windows: copy ...

# сервер (auto-reload)
python -m app.server
# или:  uvicorn app.server:app --host 0.0.0.0 --port 8000 --reload
```

Порт/host берутся из `config.json`. Сетевую автонастройку и прошивку в этом
режиме делай вручную (`scripts/net_config.sh`, `esp/flash.sh`).

## Как играть (кратко)

1. Дилер открывает `/dealer` (первый раз — `/setup`), настраивает партию
   (длина раундов, веса предметов, лимит магазина), создаёт игру.
2. Игроки открывают `/`, жмут «join game», вводят имя.
3. Дилер физически раздаёт предметы, заряжает дробовик и **дублирует каждое
   реальное действие** в панели — система ведёт HP, патроны, ход.
4. Ошибся — кнопка **undo**.
5. Секретная инфа (порядок патронов, «лекарство», результат телефона/лупы)
   видна только дилеру. Полные правила — `docs/RULES.md`.

## Типовые проблемы

- **Телефон не открывает страницу** — та же Wi-Fi? правильный IP? порт 8000 не
  режет файрвол? Проверь с хоста: `http://localhost:8000`.
- **`docker compose` не найден** — поставь Docker Desktop / docker-compose.
- **`Address already in use` / порт занят** — смени `server.port` в
  `config.json` или `./start.sh --down`.
- **`arduino-cli не установлен` / плата не найдена** — прошивка пропускается,
  сервер поднимается. Ставь плату — `brew install arduino-cli` + USB, либо
  запускай `./start.sh --no-flash`.
- **IP определился как `localhost`** — LAN-интерфейс не найден; узнай вручную:
  macOS `ipconfig getifaddr en0`, Linux `hostname -I`, и впиши в `config.json`.
- **CCTV не стартует на mac/Linux** — авто-скачка только под Windows; ставь
  MediaMTX вручную (см. раздел «Видео и камеры»).
